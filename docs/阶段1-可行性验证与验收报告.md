## 3. S01-03：ISS 位置与空间天气

### 3.1 ISS 位置

实际查询：`https://api.wheretheiss.at/v1/satellites/25544?units=kilometers`，HTTP 200。响应中的 `timestamp` 按 Unix 秒转换为 UTC，纬经度、高度与编号有范围校验。

上游 `units=kilometers` 时速度是 km/h，需除以 3600 转为平台 km/s；本次响应转换后约 7.65005 km/s。不能把第三方计算位置称为卫星遥测。最初响应时间与本机有约 2 秒偏差，诊断记录保留原始时间，不把小范围时钟差当作伪造。

官方接口目前无需 Key，约每秒一次限额；项目后续后端缓存 10 秒，用户请求复用，见 [WTIA 官方接口文档](https://wheretheiss.at/w/developer)。

### 3.2 空间天气：已验证 GFZ Kp

来源为 GFZ 官方 Geomagnetic Observatory Niemegk：

`https://www-app3.gfz-potsdam.de/kp_index/Kp_ap_Ap_SN_F107_nowcast.txt`

首次连接存在证书链问题；为项目 Python 客户端加载系统与 certifi 根证书后取得 HTTP 200，**证书校验始终开启**，未修改系统根证书或代理设置。

本次 30 个日记录、234 个有效三小时 Kp 区间、6 个尚无数据的区间。最新区间起点 2026-11-12 03:00 UTC，Kp=0.333，状态为 preliminary nowcast，不能当作最终值或将区间起点当发布时间。

格式校验：28 列，前 3 列日期，Kp1～Kp8 为三小时值；Kp 已在 0～9 尺度，**不再除以 10**。-1 表示缺失，不代表平静；D 列区分暂定与最终状态。为保守限频，本次验证缓存 3 小时；正式页面显示区间、发布时间、数据年龄与状态，刷新策略在正式数据源适配器实现时明确。

许可依据原文件头：Kp 为 CC BY 4.0，需归属 GFZ 与 Matzka 等（2021），DOI [10.5880/Kp.0001](https://doi.org/10.5880/Kp.0001)。原文件另含 CC BY-NC 4.0 的太阳黑子数，本验证不使用其字段；保留原文件头，后续若使用须单独处理相应许可。

NOAA 两个 JSON 端点仍存在本机 TLS 问题，CelesTrak 天气 CSV 返回 406，已停止请求并保留证据；406 曾审查是否由 Accept 请求头引起，修正后仍失败，因此**根因未确定**。GFZ 是已实测可用的替代，不把这些失败来源写成成功。官方预警/耀斑通知接入仍留给阶段 7，不伪造预警事件。

证据：[已选来源及快照复核](./evidence/environment-sources-2026-11-12-selected.json)、[GFZ 在线请求](./evidence/gfz-space-weather-2026-11-12.json)、[初次失败记录](./evidence/environment-sources-2026-11-12-initial.json)。脚本：[来源验证](../scripts/verify_environment_sources.py)。

## 5. S01-05：传播、坐标与数值验证

实现：[orbits.py](../backend/phase1/orbits.py)。固定验证时刻为 2026-11-12 00:00 UTC，另取 +1h 与 +24h，共 3 种轨道、9 个状态。

- 标准基准：Vallado 等 SGP4 验证用例 00005，t=0 的 TEME 位置与速度。参考位置误差约 6.82×10^-9 km；该数字是实现与参考数值的吻合程度，不是实际轨道精度。
- C++ 与纯 Python SGP4 传播对照，位置容差 10^-5 km、速度容差 10^-7 km/s；二者共享同一理论，不将其当作独立观测证据。
- 独立按 GMST1982 旋转 TEME 到 ECEF，与 Skyfield 地固坐标对照，九状态最大差约 0.061 m。
- WGS84 纬经高到 ECEF 的独立公式回算，小于 0.02 m 数值容差。
- 真实 ISS TLE 与 GP JSON 的位置最大差约 0.964 m（受格式精度和四舍五入影响，验收容差 50 m）。
- 极端/衰减轨道触发的 SGP4 错误由应用包装层转成明确失败，不向前端传 NaN。
- 与外部 ISS 服务在同一时间戳的诊断：本次地表距离差约 0.811 km、高度差约 0.011 km；两边模型和根数可能不同，不当作真实定位误差保证。

参考：[Vallado SGP4 资料](https://celestrak.org/publications/AIAA/2006-6753/)、[Skyfield 卫星文档](https://rhodesmill.org/skyfield/earth-satellites.html)、[SGP4 官方包说明](https://pypi.org/project/sgp4/)。

## 6. S01-06：北京站过境、受光与边界

固定观测站：北纬 39.9°、东经 116.4°、海拔 0 m；2026-11-12 00:00～11-15 00:00 UTC，最低仰角 10°。

本次得到 17 次过境，其中 4 次包含潜在目视窗口。用独立粗采样与二分求根校验进入/离开，最大时间差约 0.208 秒。该差值只描述数值方法一致性，不保证现实观测时间精度。

目视条件：仰角达到阈值、地面太阳高度低于 -6°、卫星受太阳照射；输出区间而非只看最高点。以 5 秒采样检测条件变化，再把已发现的边界细化至约 0.5 秒；特别短于采样步长的条件片段可能遗漏，正式观测模块需继续细化此策略，不称为精密光学可见性预测。

另外验证：跨查询边界的 10 秒窗口、90° 阈值无事件、GEO 对星下附近站点一小时持续可见。受光结果与独立球形地球遮挡射线计算在 20 个样本时刻一致；未处理半影、视星等、云层、建筑遮挡与光污染。

星历：NASA/JPL DE421，经 `skyfield-data` 7.0.0 包取得，16,788,480 字节，来源和哈希见样本清单。直接 JPL 下载失败证据见记录；不声称直接下载成功。仅使用 DE421，不使用该数据包中已过期的 IERS 文件。时间尺度采用 Skyfield builtin 数据，**没有接入精密实时 EOP/极移**，这限制了实际预测精度。

## 7. S01-07：真实后端到本地三维闭环

验证入口：[本地页面](http://127.0.0.1:5173/)。源码：[React 页面](../prototypes/phase1/src/main.jsx)、[FastAPI 只读验证服务](../backend/phase1/server.py)。

本机验证场景为 21 颗对象、6,321 个真实后端采样点，ECEF 米坐标在 Cesium `FIXED` 框架插值；前端不计算 SGP4。固定样本与推演时间清晰标注，没有冒充实时位置。

使用本地安装 Edge 的隔离 D 盘测试配置、无头模式与软件 WebGL。冷加载前拦截全部外部 HTTP，实际无外部请求，地球/轨道照常显示。该验证不等于操作系统断网或硬件 GPU 性能测试。

6 组浏览器检查通过：

1. 冷启动、本地地球、WebGL 和采样数正确。
2. 模拟时钟推进。
3. 选择、相机定位、跟踪与退出。
4. 暂停与恢复。
5. 三次重建后 created=4、destroyed=3、active=1，未留重复 Viewer。
6. 1440×900、1920×1080 无横向溢出，页面无运行时错误。

测试中发现底部工具条被侧栏/画布固有高度覆盖，已用明确栅格行与 min-height 修复，回归通过。初始逐点采样改为批量计算，避免数千次标量坐标转换；新增批量/标量一致性测试。缺少全目录缓存的新检出环境也有三颗提交样本的离线回退。

截图：[1440×900 实际页面](./evidence/phase1-globe-1440x900.png)。记录：[浏览器验收](./evidence/phase1-browser-2026-11-12.json)、[初次布局问题](./evidence/phase1-browser-2026-11-12-initial.json)。

基础地球使用 Cesium 自带 NaturalEarthII 低级别瓦片，目的是验证离线可用，不代表最终 A 风格高清地球。软件 WebGL 下截图约十余帧/秒，不据此声称正式页面达成 60 FPS。大目录性能、长期运行、完整可访问性和动画精修仍按阶段 3、4、9 验收。
