# 第二批可信分析与科研实验

在「历史遥测」生成报告后，从「更多 → 可信分析」选择主报告。首次体验可选择 OPS-SAT 片段 8。每个账号能看到自己的报告和任务。页面支持两份报告的来源比较、结构化结论核验、科研任务运行和实验包下载。

## 比对与核验

选择两个独立来源的报告。系统先核对 NORAD 编号、通道、观测方式、站点和测量单位，然后按 UTC 时刻对齐通过质量筛选的测量。数量、单位、不可比原因和双方原始字段均可回查。比较以相同通道名表示同一已登记物理量为前提。来源独立性通过文件摘要和登记来源检查，仍依赖导入者正确声明资料出处。

从主报告生成一条待核验结论，修改数值、统计量引用、时刻、对象或单位后运行。服务端从账号可访问的冻结报告核对样本数、均值或极差，并保存原始输入、核验状态、可复算的修正及其引用。未知单位阻止物理量换算。点击核验结果可回到原始记录和参与计算的样本列表。

## 任务与模型

固定流程可直接分析同一份报告。选择模型时，用户的分析请求传给配置的模型，模型在 archive、quality、detect、verify、summary 五个只读工具中选择。服务端锁定报告、账号、片段与版本，按依赖排序，保存原始模型计划。检测步骤实际复跑档案。模型挑选总结栏目，引用和数值取自核验工具。适合本机模型的匿名游客样本限定在公开 OPS-SAT 案例。

任务状态、步骤、模型名、工具输出、耗时、失败原因及重试历史可导出。最多尝试三次。取消阻止后续步骤与结果发布；进行中的模型 HTTP 调用有超时。超过两分钟未更新的排队或运行任务可标记中断并重试。实际任务库位于项目的 `.local/data/telemetry/cases.sqlite3`。

服务端读取环境变量或项目根目录 `.env` 中的 `STAR_QWEN_URL`、`STAR_QWEN_MODEL`、`STAR_QWEN_KEY`，DeepSeek 使用 `STAR_DEEPSEEK_` 前缀。URL 填写兼容 Chat Completions 的基址，本机示例为 `http://127.0.0.1:8031/v1`。本机记名模型与 GGUF 摘要见[模型清单](./evidence/phase15-model-runtime.json)。公网服务要求 HTTPS；密钥只在后端读取。团队服务可参考 [DeepSeek 接口文档](https://api-docs.deepseek.com/) 和[百炼接口文档](https://help.aliyun.com/zh/model-studio/compatibility-of-openai-with-dashscope)。

## 实验复跑

以下命令从仓库根目录运行。模型实验需要对应推理服务在线。产物保存在项目运行目录，页面按当前登录账号提供实验包下载。

```powershell
backend/.venv/Scripts/python.exe scripts/telemetry_benchmark.py .local/data/telemetry/segments.csv .local/data/telemetry/tian-shu-bench-v1.zip
backend/.venv/Scripts/python.exe -m scripts.evidence_benchmark .local/data/telemetry/evidence-bench-v1.zip
backend/.venv/Scripts/python.exe -m scripts.model_benchmark qwen docs/evidence/phase16-qwen-plans.json
backend/.venv/Scripts/python.exe -m scripts.agent_evidence_benchmark qwen docs/evidence/phase16-qwen-policies.json
backend/.venv/Scripts/python.exe -m scripts.model_benchmark deepseek docs/evidence/phase16-deepseek-plans.json
backend/.venv/Scripts/python.exe -m scripts.agent_evidence_benchmark deepseek docs/evidence/phase16-deepseek-policies.json
backend/.venv/Scripts/python.exe -m scripts.model_experiment_package .local/data/telemetry/model-bench-v1.zip
```

异常检测使用原数据的 train 列固定分组。1,594 个开发片段和 529 个测试片段分别计分。同一片段内任何样本触发阈值，记一次片段级检出。MAD 在测试集上 TP 28、FP 111、FN 85、TN 305；三倍标准差 TP 12、FP 1、FN 101、TN 415。[检测结果](./evidence/phase16-opssat-benchmark.json)

证据实验在不同片段构造开发与测试任务，每组五类单字段错误和一个正确对照。测试组完整规则拦截 5/5、正确放行 1/1。消融结果显示去掉对应检查后的变化。[核验对照](./evidence/phase16-evidence-ablation.json)

工具计划对照使用两个开发请求和三个留出请求，比较单次调用与规划后再复核的两次调用。两组允许生成的总 Token 均为 192，输入长度、实际 Token 和耗时分别记录。原始顺序完全匹配和服务端依赖排序后的匹配分开统计。证据判分的四组对照共享同一原始资料和单字段故障，分别记录直接接受、确定性校验、模型选择是否调工具及模型加必经校验的结果。小样本只用于验证流程和发现失败模式。


## 本机联调结果（2026-11-27）

Qwen2.5-0.5B-Instruct 和 DeepSeek-R1-Distill-Qwen-1.5B 使用本机 llama.cpp CPU 服务，分别完成公开案例的计划、档案、质量、检测、核验与报告生成。DeepSeek 使用 Q4_K_M 蒸馏模型与 0 推理 Token 预算。DeepSeek 官方 API 也已通过正式账号和公开样本联调。两个模型选出的报告栏目均由服务端绑定冻结报告的数字与引用。[Qwen 运行](./evidence/phase15-qwen-job.json) · [DeepSeek 运行](./evidence/phase15-deepseek-job.json)

三个留出任务的单次调用原始计划顺序完全命中数分别为 Qwen 0/3、DeepSeek 1/3。服务端依赖排序后分别为 2/3、1/3。增加一次模型复核后的原始顺序命中均为 0/3。固定输入下，两个模型对测试组五项错误均直接接受，正确对照也接受。加入确定性校验后均拦截五项错误并保留正确对照。此次样本量不足以推断总体准确率。[计划评分](./evidence/phase16-model-scores.json) · [Qwen 四组对照](./evidence/phase16-qwen-policies.json) · [DeepSeek 四组对照](./evidence/phase16-deepseek-policies.json)

第二批的 32～39 项映射至比对与证据核验；40～56 项映射至固定上下文、两种模型、工具调用与持久化任务；57～65 项映射至检测基准、控制错误、消融、单角色与双角色对照及三个实验包。记录与评测均限定于本文列明的统计量、工具、模型和数据。

DeepSeek 官方服务在「执行方式」中单列。配置使用服务端 `STAR_DEEPSEEK_CLOUD_URL`、`STAR_DEEPSEEK_CLOUD_MODEL`、`STAR_DEEPSEEK_CLOUD_KEY`，本次使用 `https://api.deepseek.com` 和 `deepseek-flash`。本机 DeepSeek 模型继续使用 `STAR_DEEPSEEK_` 配置。官方服务仅对正式账号开放。[官方 API 实测](./evidence/phase15-deepseek-cloud-job.json) · [浏览器下载实测](./evidence/trusted-delivery-browser.json)
