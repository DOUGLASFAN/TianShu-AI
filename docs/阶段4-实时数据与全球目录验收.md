## 已实现

### 定时采集

`backend.worker --serve` 是独立进程，启动/停止脚本已纳入管理，主要运行数据继续保存在项目 D 盘目录。新增 `runtime_states` 表及迁移，保存任务状态、下次时间、上次成功和有效数据。任务通过独立线程运行，并使用 PostgreSQL 会话锁防止多个 worker 重复执行。

| 任务 | 正常周期 | 实际行为 |
| --- | --- | --- |
| 轨道根数 | 2 小时 | CelesTrak 来源策略、验证后原子入库、采集记录；本机实际成功导入 16,899 条 |
| ISS 外部位置 | 10 秒 | Where the ISS at? 实际 HTTP 成功，检查坐标、单位和来源时间，km/h 转 km/s；不是卫星遥测 |
| 统计缓存 | 5 分钟 | 唯一 NORAD 目录数量与归属覆盖量，写 Redis 和数据库有效版本，统计接口返回缓存年龄 |

失败不清空有效数据；从至少 60 秒开始指数退避，考虑正常周期和上游 Retry-After 秒数。轨道来源请求仍遵循原有 2 小时 TTL。定时状态在重启后保留，持锁进程退出造成的中断任务可恢复。每个任务保留最近 100 条执行记录，轨道采集另有业务采集日志。

ISS 最初出现 TLS 失败，加入系统证书与 certifi 信任链后实际采集成功，全程未关闭证书验证。上游[开发文档](https://wheretheiss.at/w/developer)说明约每秒一次请求限制，10 秒周期低于该限制。两小时周期采用持久化时间和可控时钟测试验证，没有声称已等待完整两个小时观察第二轮线上请求。

### 实时连接

新增 `POST /api/realtime/ticket`、`WS /api/realtime/ws` 和受保护的状态回查接口。票据由已登录会话申请，30 秒有效，一次性消费；数据库仅保存摘要，响应禁止缓存。JWT 和票据不放在 WS URL 中。

服务器校验 Origin、用户、会话与角色状态，每 10 秒检查授权及心跳；客户端失联超时关闭。连接首次发送完整快照，此后只发送变化的状态字段。订阅限于一个卫星，输入有长度/编号限制，快速更换保留最后目标，所选轨迹按需更新。

前端采用带抖动的指数退避，重连重新申请票据并接收快照。每条消息带连接 streamId 和递增 seq，旧连接与乱序消息被丢弃。退出/禁用导致授权失效时停止连接并返回登录。没有以页面按钮隐藏代替服务端授权。

Vite 与 Nginx 已配置 WS 转发。Compose 增加 worker 服务，但仍未运行 Docker 容器，不能将配置交付当作容器部署成功。

### 全球目录与总览

探索页“更多筛选”提供国家/组织、用途和轨道类型，复用分组与分页。统计以唯一 NORAD 编号为准，分组数量不可相加作为总卫星数。

用途只读取来源中的 `PURPOSE`，当前来源缺失时统一为“未知”，不依据名称或所属国家编造用途；覆盖数量在 facets 和验收 JSON 中保留。轨道分类互斥：LEO 远地点小于 2000 km；GEO 周期接近 1436 分钟且低偏心率；其余符合范围的 MEO；余下为 HEO，缺失标未知。分类是本平台说明过的统计口径，不等同权威轨道类别标签。

“全球总览”使用 `SatrecArray` 批量计算，TEME 转 ITRS/ECEF。当前 16,899 颗全部成功计算。每个窗口 45 秒、前端约每 20 秒更新，区间内插值，区间外隐藏点位。总览上限为 20,000 个候选，超过时返回明确截断标志及目录总数。本次目录没有截断。

Cesium `PointPrimitiveCollection` 批量绘制点，不为每颗卫星建立轨道和标签。标签优先当前对象，详细空间轨迹与地面投影各最多一条。切换总览和离开页面清理集合与 Viewer。选中对象仍使用详细采样，全球总览不是每颗卫星的精密连续预测服务。

### 状态与降级

连接状态、时间模式、根数质量独立展示。“数据状态”可展开查看来源、根数历元、采集时间、ISS 来源时间与采集状态；总览缓存原始生成时间及年龄单独显示。网络已连接不代表根数新鲜，也不将历史根数推演当成遥测。

Redis 故障时任务可写数据库有效版本，目录及认证继续使用数据库。上游失败保留之前的有效数据和原始时间。全球总览保存项目内公开数据快照，后续读取失败可在允许的鉴权边界内回退；历史窗口之外不绘制伪实时位置。

**鉴权依赖数据库：数据库完全不可用时，新请求不能绕过身份校验读取快照。** 已加载页面保留数据并显示请求失败，旧位置超出区间后隐藏；数据库恢复后 WS 重连补快照。浏览器历史快照检查使用明确故障注入，数据库异常的服务层回退另有测试，未声称匿名离线访问可用。

## 首轮性能

实测为 1920×1080、DPR 1，隔离 Edge/Chromium 157，**强制 SwiftShader 软件 WebGL**。机器为 Ryzen 9 7945HX、32 逻辑处理器，检测到 RTX 4060 Laptop GPU，但此次浏览器没有用它做硬件帧率验收。

第二轮记录：16,899 点，后端批量计算约 **1058 ms**；页面首次总览加载约 **2028 ms**；JSON 载荷约 **1.28 MB**；8 秒窗口观察约 **2.37 帧/秒**。这些是一次受控检查的观测值，不是 P95，也不证明真实 GPU 达到目标帧率。详细原值以 JSON 为准；阶段 9 仍需做硬件渲染、长时间稳定性和性能优化验收。

```powershell

backend/.venv/Scripts/python.exe scripts/verify_phase2_backend.py --stage 4
npm run build --prefix frontend
backend/.venv/Scripts/python.exe -m scripts.verify_phase4_delivery
```

## 2026-11-15 总览连续性修订

原 45 秒单窗口替换存在页面时钟落后时整批隐藏的缺陷。现改为生成时间前 15 秒至后 45 秒的窗口，前端保留最多三批并复用集合；只有全部窗口均不覆盖页面时刻才隐藏。历史性能与范围记录保留，新行为及验证见[点位消失修复](./全球总览-点位消失修复.md)。
