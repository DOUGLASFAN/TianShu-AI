## 1. 标记与更新规则

- `[x]` 表示该项交付物已完成且达到通过条件；`[ ]` 包含未开始、进行中、待验证或受阻，具体状态写在条目下。
- 编写代码但未验证标记“待验证”，不能提前勾选。文档完成不等于对应功能完成，效果图不等于浏览器原型。
- 每完成一项，在同一次工作交付中更新勾选、完成日期、验证方法/结果和可追溯证据，同时更新阶段状态、总览和变更记录。
- 每个阶段只有必做条目全部通过，才标记阶段完成。阶段验收不自动增加用户确认步骤，普通实现按既有授权推进。
- 验证失败或后续回归应取消勾选，记录原因、影响与后续处理；不能让旧的完成状态掩盖已知缺陷。
- 证据可以是文件、数据库迁移、明确的测试/操作记录、截图或录屏。只有文件存在不能证明运行正确。
- 算法、权限、数据持久化与异常处理采用相应验证；不为每个可逆样式调整机械增加测试。
- 任务拆分或范围变更保留旧 ID 与原因，不删除未完成项制造完成率。可选增强单列，不计入必做分母。
- 本清单为唯一逐项进度来源；实施路线记录顺序，需求文档记录范围，其他文档不重复维护勾选状态。
