# 阶段 10 · 部署与答辩交付

交付版本 `StarNexus-2026.11.21-rc1`。2026 年 11 月 21 日完成 Windows 原生部署、数据库恢复、演示和归档验收。

## 首次运行与日常启停

准备 Windows PowerShell、Node.js 24 和 Python 3.12。首次安装依赖需要联网。解压源码后，在项目根目录运行：

```powershell
./scripts/prepare.ps1
./scripts/start.ps1
```

打开 [星枢](http://127.0.0.1:5174/) 和 [API 就绪检查](http://127.0.0.1:8001/api/health/ready)。脚本安装锁定依赖、准备 Cesium 静态文件，按顺序启动 PostgreSQL、Redis、迁移初始化、API、worker 和前端。原生默认账户与口令见 `.local/config/demo-accounts.json`。停止执行 `./scripts/stop.ps1`，加 `-KeepServices` 可保留 PostgreSQL 和 Redis。依赖、服务数据和运行日志均保留在项目目录。进阶配置见[原生服务说明](./阶段2-部署与启动说明.md)。

第一次答辩前，在服务运行时执行 `backend/.venv/Scripts/python.exe -m backend.app.demo_seed`。使用 `xingxu_demo` 登录，口令见 `.local/config/showcase-account.json`。当天重复运行可复用已生成的记录；跨日重新运行可生成新的未来过境计划。

本次独立验收从新的源码副本安装依赖，使用独立数据库、Redis 逻辑库和签名密钥，完成迁移、初始化、生产构建、登录、目录读取和静态素材访问。原数据库保留。验证复用了本机 PostgreSQL 和 Redis 服务进程。[新配置实测](./evidence/phase10-fresh-config-2026-11-21.json)。

### Compose 部署

有 Docker Engine 的机器可从 `.env.example` 准备环境变量与强口令后执行：

```powershell
docker compose config --quiet
docker compose up --build -d
docker compose ps
docker compose down
```

应用入口为 `http://127.0.0.1:8080/`。容器数据库和缓存与原生实例分开保存；保留数据时用常规 `down`。本机已用官方 Compose CLI 校验配置，容器启动和容器内健康检查待有 Docker Engine 时运行。[Compose 校验记录](./evidence/phase10-compose-2026-11-21.json) · [官方 CLI 发布页](https://github.com/docker/compose/releases/tag/v5.7.0)。

## 备份、恢复与排查

Windows 原生数据库运行时执行：

```powershell
backend/.venv/Scripts/python.exe scripts/backup_restore.py backup
backend/.venv/Scripts/python.exe scripts/backup_restore.py verify .local/backups/实际备份文件名.dump
```

把同名 `.dump` 和 `.json` 成对保存在私有存储。备份和表计数取自同一数据库快照。恢复会验证 SHA-256，在独立的 `xingxu_restore_*` 数据库中执行单事务恢复，并核对表行数及迁移版本。需要切换时，先在独立配置中指向恢复库，验证登录、计划、历史预测与回放，再安排维护窗口切换连接。保留旧库以便回退。Redis 用于缓存和任务协调，持久业务记录以 PostgreSQL 为准。[实际备份与恢复结果](./evidence/phase10-backup-2026-11-21.json)。

- **启动失败**：确认 Node、Python、依赖准备结果和 5174 / 8001 端口占用。就绪接口返回失败时，检查本机服务日志及数据库迁移。
- **无法登录**：按账号来源查看本机对应口令文件。先检查 API 就绪，再检查前端请求是否指向正确实例。
- **轨道根数陈旧、近地底图模糊**：查看探索页“数据状态”和底图选项。断网演示使用本地快照与底图，高清影像依赖外部地图服务。
- **回退应用版本**：解压此版本到新目录，准备依赖并使用独立配置对恢复库做验收，确认后切换入口。保留运行中的原目录与备份。

## 系统与数据口径

React / TypeScript 管理界面与交互，Cesium 渲染地球、轨道与点位，FastAPI 提供 HTTP 与实时通信，PostgreSQL 保存用户、观测站、计划、目录和审计，Redis 配合后台任务及实时数据。角色权限区分个人操作和管理中心。HTTP 接口以[当前 OpenAPI 描述](./交付/openapi.json)为准，实时 WebSocket 与初始化细节见[工程接口文档](./阶段2-接口与数据库说明.md)。

轨道来自公开轨道根数，使用 SGP4 推算并转换到地固坐标。以 WGS84 站点计算仰角、方位、距离与过境区间。潜在目视窗口结合最低仰角、站点太阳高度和卫星受光条件，实际观测还受云层、光害和地平遮挡影响。采样方案加载时使用当时目录根数重新推算，需复现原采样时可保留导出的 JSON；已保存观测计划保留计算快照。实时态势展示推算点位，回放使用所选时间区间。界面时区只影响显示。

轨道与目录复用 CelesTrak 等公开来源的快照，空间环境按实际启用的来源展示观测时间和健康状态。影像、太空素材与模型沿用各自署名，网络不可达时使用已随包提供的本地资源。近地高清地图及可选地图密钥仍由运行环境提供。参见[素材与署名](./高清星空与电影视角试用验收.md)、[数据与算法可行性](./阶段1-可行性验证与验收报告.md)、[性能与稳定性实测](./阶段9-综合验收报告.md)。

## 答辩路线与录像

1. 登录演示账号进入「卫星探索」，打开「全球总览」和「数据状态」，展示目录数量、生成时间、来源，点击卫星看详情。
2. 在「观测规划 → 历史计算」打开「演示 · ISS 与天宫」，展示过境结果、整组回放和时间轴。
3. 在「我的空间」打开已保存计划并回放，展示已保存的观测时间与轨迹。
4. 外网不可用时保持本机服务运行，按相同步骤查看已缓存的数据和计划。第二段录像用浏览器隔离外部 HTTP 和在线瓦片请求，保留本机接口。
