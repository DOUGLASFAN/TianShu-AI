## 使用流程

在“观测规划”选择站点，切换“卫星分组”，选择分组、每批 25／100／500 颗及批次。页面显示目录总数、实际本批数量、NORAD 起止和完整对象列表。编号升序稳定分页；提交附带确认过的编号列表，目录改变导致范围不同则返回“批次已更新”，不静默换一批。

任务在独立 worker 中排队。进度展示已完成对象数、缓存命中数和失败对象，允许取消；个别传播失败明确列出，其他有效结果保留，全部失败不会伪报成功。完成后可按进入时间／最高仰角排序、筛选潜在目视窗口及翻页。选择事件只预览，不自动播放。

单星查询点击“回放过境”、分组结果点击“单星回放”，默认从过境前 60 秒至结束后 60 秒、10×播放。暂停、拖动、Home／End／方向键、指定时间、1／10／30／60×、从头和回到当前均可用。单星模式换事件先退出旧回放。回放时钟不修改真实系统时钟，也不改变服务端计划和提醒时间。

分组任务另有“整组回放”，从完整查询起点开始，可播放整批最多 500 颗。下拉或地图点选卫星保持时钟；只为选中对象显示名称、轨迹与地面投影，下方曲线显示同一加载窗口。地图全部点位的载入数、达到站点仰角要求的数量分别显示，颜色配有文字图例。选中对象没有过境时仍有点位与窗口曲线，并明确提示；事件表的分页和筛选不会裁掉整批对象。

未来事件可保存观测计划，提前 5／10／30 分钟任选其一；重复保存同一任务同一事件返回已有计划。事件已开始则拒绝保存为未来计划；提醒时间已过但事件尚未开始时，允许保存并标明“已错过”，不冒充准时提醒。根数更新后要求重新计算，陈旧根数需要明确接受误差。

在“我的空间”查看计划、状态、快照和版本，或回到计划快照回放。“重新计算”带入原卫星、站点和条件，计算后选择未来事件并点击“更新计划”：先展示新旧时间、仰角、站点、根数历元及提醒阈值，确认后才生成下一版本。旧版本不改写，旧提醒时间撤销；取消与重算发生竞争时以版本检查结果为准。

**本阶段只持久保存并重排提醒意图，尚不发送通知。** 保存弹窗已明示该限制，实际投递与站内提醒在阶段 7 实现。

## 存储与执行

迁移 `eae2f066fe2f` 承接 `e520261115`，为既有预测添加执行统计并建立六张表：

| 表 | 用途 |
| --- | --- |
| `prediction_events` | 分组事件摘要与完整曲线分列，按任务／事件键读取；起始时刻、最大仰角和目视标记可分页筛选 |
| `prediction_cache` | 两小时物理计算缓存，键包含站点经纬度／海拔、时间、天数、阈值、原始根数／版本和算法 |
| `observation_plans` | 用户归属、不可变来源快照、状态、当前版本及提醒阈值 |
| `plan_versions` | 创建、取消、重算确认的历史版本与快照 |
| `plan_reminders` | 按计划／版本／阈值去重的真实 UTC 提醒时间和 pending／missed／cancelled 状态 |
| `plan_proposals` | 十分钟有效的重算差异预览，绑定预期版本，确认可安全重试 |

六张新增表不覆盖已应用迁移。JSON 快照保留根数、站点、事件、算法和来源，不依赖原站点或预测任务继续存在。计划删除原站点／来源任务后仍能读取和回放。

单个任务上限 500 颗、每用户最多 3 个活跃任务、全局最多 32 个。沿用 PostgreSQL 租约，整个队列仅一个消费协调者；小批使用最多四个计算线程，大批使用四个独立数学进程，并由线程协调缓存读写及分段落库。数学子进程观察实际父进程句柄，Windows 强制停止父 worker 后不会留下孤立计算进程。服务重启将中断任务标记为 `WORKER_INTERRUPTED`，清理未完成事件；不会把半批结果当作完整结果提供。

缓存复用不会改写根数依据。事件保留是否命中缓存和原计算时间，任务另记本次开始／完成时间。分组详情按当前事件的卫星读取根数，不能显示分组首颗卫星的根数冒充当前事件依据。

## 回放一致性

2026-11-15 补充说明：首轮阶段 6 将分组预测后的单事件回放视为“回放完成”，漏掉整批多星同时回放。按用户反馈扩展原 S06-04／05 的通过条件，先撤回两项勾选，补齐后单独复验；未增加必做分母，也未提前启动阶段 7。

后端从保存的 GP 根数生成 ITRS/ECEF、WGS84、站心仰角／方位／距离、太阳高度及受光采样。回放请求上限 2001 个样本，默认约 5 秒步长；长事件按实际长度扩大步长，响应记录实际值，不外推。曲线、卫星和地面点共用前端唯一模拟时间，客户端显示精度为毫秒。

地图中的卫星轨迹和地面投影是同一数据源，回放时光照使用该模拟时间；退出清理动态点和轨迹、恢复当前时刻。切后台暂停，避免回来后跳过整段。潜在目视仍是几何／太阳高度／受光共同条件，不含星等、天气、地形和折射。

整组从任务保存的完整 `basis.targets` 和根数读取，采用 SGP4 向量传播至 ITRS/ECEF；每五分钟切换缓存桶，每个窗口最多 20 分钟、61 个样本、步长不超过 20 秒，首尾按查询边界裁切。服务端最多缓存四个窗口，客户端过期窗口回收，不下载整批七天全轨迹。点位线性插值，站心仰角、方位和距离按插值位置重算；这是可视化采样，不替代后端精化的过境边界。选中曲线标为“窗口采样最高仰角”，避免冒充完整过境最高点。无窗口时隐藏旧点并显示加载状态，失败对象明确列出，不外推。

整组使用一个 Cesium 点集合；对象切换复用点位，只有选中星的标签／轨迹／投影额外绘制。全球取景按实际轨道半径容纳本批，MEO／GEO 批次中地球相对较小是实际比例，可使用“定位观测站”或缩放调整视角。几何阈值筛选与潜在目视窗口是不同条件。

## 接口

| 方法 | 地址 | 行为 |
| --- | --- | --- |
| GET | `/api/predictions/groups/{slug}/batch` | 稳定批次预览、总数、上限与实际编号 |
| POST | `/api/predictions/groups` | 校验已确认的对象范围并创建后台任务 |
| GET | `/api/predictions/{id}/results` | 单星／分组统一分页、排序、目视筛选 |
| GET | `/api/predictions/{id}/events/{eventId}` | 事件与对应卫星的计算依据 |
| GET | `/api/predictions/{id}/events/{eventId}/replay` | 有界统一回放数据 |
| GET | `/api/predictions/{id}/group-replay?at=ISO` | 按保存批次生成整组有界轨迹窗口，包含失败清单与实际载入数 |
| GET | `/api/predictions/{id}/group-replay/satellites/{norad}?at=ISO` | 校验批次内对象，读取对应根数和当前／最近过境；没有事件时返回空事件及有效依据 |
| GET / POST | `/api/plans` | 私有状态筛选／分页、幂等保存 |
| GET | `/api/plans/{id}` | 当前快照与历史版本 |
| POST | `/api/plans/{id}/cancel` | 按预期版本取消并撤销提醒 |
| POST | `/api/plans/{id}/preview` | 保存新旧差异预览，不改变当前版本 |
| POST | `/api/plans/{id}/changes/{changeId}/confirm` | 再校验真实时间、根数和版本，确认后更新 |
| GET | `/api/plans/{id}/replay` | 使用计划快照回放，不依赖原任务存续 |

所有读取、回放、保存、预览、确认和取消均检查用户归属；回放时钟不进入这些状态判断。跨页 URL 保留任务、事件、筛选、分页以及尚未重算的表单条件；登录用户变化时清除前一个用户的导航上下文。
